三、执行流水线（五阶段）

Phase 0理解需求
DeepSeek 理解需求
输入：--requirement（+ 可选 --design-context 硬约束注入）
结构化需求：目标 / 功能 / 边界 / 技术约束 / 交付物清单 / VISUAL: yes|no 判定
输出 pipeline_artifacts/requirement.md
↓
Phase 1设计 ∥ 视觉
GLM 5.3 整体设计
文件清单（### FILE: 路径 + 依赖分组）+ 逐文件规格 + 接口 / 数据模型
只设计不写码；已有 --design-context 时不得重做选型
输出 design.md（文件清单解析为待编码列表）
Qwen3.8-Max 视觉与 UI 设计
页面 / 组件 / 配色 / 图表规格（仅 VISUAL: yes 时启用；纯后端跳过）
输出 visual_spec.md
↓
Phase 2路由编码（GLM/Qwen）
route_coder() — 确定性二分流（按扩展名，无 LLM 参与）
① 扩展名 ∈ {.html .css .svg .vue .jsx .tsx .mdx}？ ── 是 ──→ Qwen3.8-Max（UI 文件，对照 visual_spec）
└─ 否（常规 / 大文件 / 新文件）──→ GLM 5.3（编码位，1M 上下文承接全文重写）
编码提示词强制：完整输出全文、禁止省略、禁止以注释代替内容、禁止改写与任务无关部分。 同依赖组文件并行派发（ThreadPool）；依赖文件内容（≤4K 字）注入上下文。
写入 safe_path() 定位 → 写后校验（回读非空）
↓
Phase 3双审查
GLM 5.3 代码审查
逻辑 / 安全 / 规格一致性 / 风格（.py/.js/.ts/.go 等主审）
输出 review_code.md（✅ 通过 / ⚠️ 位置 + 修改建议）
Qwen3.8-Max 视觉产出审查
playwright 启动服务 → 截图（存 .visual_tmp/）→ base64 直发模型，对照 visual_spec 逐项核对布局 / 配色 / 可读性
输出 review_visual.md
↓
Phase 4修复集成
DeepSeek 汇总修复 · 集成验证
汇总双审查意见 → 逐文件应用修复（同 safe_path + 写后校验）→ 交付物落盘核查（存在性 + 字节数，修复前后无变化即报「修复无效」）→ 最终报告
输出 修复后的代码 + final_report.md（报告只能引用核查表事实）

四、路径安全与落盘保障

机制规则
safe_path()绝对路径（GLM 设计清单常给绝对路径）与相对路径统一归一 → 只允许落在 project_dir 之内，越界 / ../ 断言拦截。修复 2026-08-18「产物写入嵌套错误目录」缺陷
写后校验每次写盘后回读验证非空，空文件当场报错
落盘核查Phase 4 结束后逐文件核查存在 + 字节数，输出核查表注入最终报告——杜绝「报告声称完成、文件一字未动」
